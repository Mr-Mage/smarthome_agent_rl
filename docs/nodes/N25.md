# N25 原模型与SFT配对验收

问题：训练loss下降不证明规划改善，需同harness、同预算的真实任务比较。

方案：四个单卡actor均服务原模型/LoRA，按模型隔离Gateway；同task×seed固定同物理actor，64总槽。校准12×两臂×三种子=72，eval48×两臂×三种子=288；只评估一个冻结adapter，不重训、不选择checkpoint。

结果：全部360次核验。eval各144次，G/SFT成功51/24（35.42%/16.67%），ΔSR=-18.75pp，任务聚类95% CI[-27.78,-9.72]pp；seed42胜/负1/11，配对p=0.00635。非法执行31→125，未完成2→20；tokens+9.57%，全部tokens/成功131,126→305,295（+132.83%）。成功与安全门槛失败，保留原模型+G。

归因证据：格式拒绝6→0、输出tokens减少61.68%，但SFT出现80次房间查询错误，20次步数耗尽；短回复没有改善状态绑定与结束判断。case16将`study_room`误写成`study`，失败后声称设备不存在；case79仅On却称启动，注册Off代替Pause并误关dryer。正例case74补开浴室灯，seed42仅此一胜。数据规模/覆盖、thought改写与训练强度的贡献未单独消融，不据此否定所有SFT方案。

成本与限制：全流程918.61秒，H100预留3,674.42 GPU秒；Agent P50 21.44→11.08秒，失败及未完成更多，不能当可用效率提升。所有48任务有历史暴露，仅为训练任务隔离开发诊断；A800分摊未测。四卡释放，常驻judge保留，剩余95任务未使用。

证据：`runs/sft-pilot/n25-v1/{selection.json,case-review.json,error-diagnostics.json,resource-cost.json}`、smoke/dev报告及模型概率预检。评测源码`3c09e1a`，训练adapter`30bc6e43…`；节点提交见`git log -- docs/nodes/N25.md`。
