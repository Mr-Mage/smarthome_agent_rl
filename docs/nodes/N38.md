# N38 Executable Device Contract

问题：Guard 的确定性规则散落在设备类型和命令分支中，未知能力容易以 `uncovered` 形式继续流转。

方案：新增 `DeviceContract / FunctionContract / ArgumentContract / Assertion` 和 `ContractRegistry`。Contract 只描述 capability、function、参数类型/范围/enum 及公开状态断言；未知设备、能力、函数和断言均返回结构化 reason code。保留旧 Guard 作为兼容路径，Contract 验证通过显式 `contract_blocking` 接入。

结果：新增设备类型无需修改 Guard 核心代码；未知 contract 返回 `UNSUPPORTED_DEVICE_CONTRACT`；schema、范围、能力和前置条件分别返回 `ARGUMENT_SCHEMA`、`ARGUMENT_RANGE`、`UNSUPPORTED_CAPABILITY`、`PRECONDITION_FAILED`。5项 Contract 测试通过，旧 Guard 行为不变。Contract blocking 保持显式关闭，未宣称 benchmark 收益。

提交：`d7364ff`。证据：`smarthome_agent_rl/device_contract.py`、`tests/test_device_contract.py`。
