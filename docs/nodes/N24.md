# N24 单轮四卡LoRA SFT

问题：经工具验证的少量轨迹能否让9B学到正确工具决策，需要真实训练及权重证据，不能仅凭API预检判断。

方案：冻结N23数据，四卡DDP、每卡batch1、累积4，rank16/alpha32/dropout0.05、LR1e-4、单轮。只训练语言LoRA及当前assistant目标；启用非重入检查点，不使用eval选checkpoint。独立环境及原模型保持不变。

结果：四rank各91微批次、全局23次更新；361原始样本加3个已记录的sampler补齐样本，监督21,960 tokens。训练43,278,336个参数；248个原本为零的LoRA B张量均非零，全部权重与loss有限。平均动作loss=0.2632，首/末各四微批次均值1.1693/0.0714，来自不同样本，不作为质量评测。

成本：训练阶段356.97秒；含进程初始化与合并436.75秒，四卡预留1,747.01 GPU秒，峰值分配28.65GB。单卡最长样本预检65.84秒另计，无优化器更新；A800常驻服务未停止。

验收：adapter及独立merged权重SHA复核通过，原9B八份身份文件SHA未变，语言检查点确实启用。成功率与成本收益由N25同轮配对评测判断，训练loss不作替代。

证据：`runs/sft-pilot/n24-v1/{protocol.json,training-validation.json,completion.json,merge-receipt.json,resource-cost.json}`及各rank日志；训练源码`44b61fd`，adapter SHA `30bc6e43fd610b2ec405ac09eda0db9617faa91b667b72461255661097813b0a`；节点提交见`git log -- docs/nodes/N24.md`。
