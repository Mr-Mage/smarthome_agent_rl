# N8 并发性能验收

问题：两路串行推理利用率低；扩并发后，官方工作流评测形成长尾。

方案：独立模拟器槽共享 actor，保持任务配对；测 2–64 请求并发、前缀缓存与 CUDA Graph，再比较 32/64 槽及工作流优先调度。保持权重、生成参数、步数、模拟器动力学和 judge 规则；模型身份校验与 dev 并行。

结果：回放输出吞吐 87.98 → 2,468.12 tokens/s，无请求错误。32 槽工作流优先试跑 120 次用时 230.86 秒，原顺序 271.56 秒；64 槽为 282.23 秒。选 32 槽，全量推算 43.86 分钟；各试跑均通过独立核验。

验收阻塞：`acceptance-v1` 完成 600 dev（923.48 秒），但一例 B0 工作流的字符串型嵌套 `args` 导致原 simulator TypeError/HTTP 500，evaluator −1；整轮无效，final 未启动，总成本 1,016.53 秒。已独立重放复现，并修复 evaluator 错误不能即时停止的问题。不得用预测替代完整 1,368 次验收。

修复：用户要求实施计划后，应用最小参数类型检查，未转换参数；SimuHome 独立提交 `e202971`，补丁见 `patches/SimuHome/command-args.patch`，依赖锁记录原任务快照与新运行时。实际重放 HTTP 500 → 200。

验收：`acceptance-v2` 在 `bfb76e0` 独立 worktree 中完成1,368次，耗时2,630.52秒（43分50秒），通过≤60分钟门槛。服务与探针529.87秒，dev925.65秒，final1,138.56秒；模型身份校验与dev并行。5,797个dev文件与7,350个final文件独立核验通过。

结果：dev成功数B0/G/GV/GC/Full=40/40/39/43/38（各120）；旧final性能复跑B0/G/GC/Full=65/72/75/74（各192），不替代原N6正式结果。旧失败轮保留，v2在验收结束、端口释放后启动。

证据：服务器 `runs/concurrency-capacity/preflight-v1`–`v5`、`acceptance-v1`；本机错误收据 `outputs/concurrency-capacity/acceptance-v1-error/`。51 项测试通过。版本：`c9ac1b4` 调度、`bb489f2` 首轮验收、`c45d969` 即时停止；文档提交见 `git log -- docs/nodes/N8.md`。指标持续维护于 `docs/实验报表.md`。
