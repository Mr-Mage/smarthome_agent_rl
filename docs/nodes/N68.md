# N68 原生资源冲突与Agent上下文

问题：N49冲突检测只有离线接口，真实原生调度未登记资源目标，Agent也看不到持久Job摘要。

方案：新增可选GTMEC，沿用GTME事件监督；从已观测设备结构与实际调度参数提取固定目标，末次已知写入覆盖前次。未知后续命令清除该设备已有声明；未来状态引用不解析。按原2秒闭区间检测冲突，不推断持续占用、不自动仲裁、取消或重放。新Job登记后向下一次真实请求追加摘要，最多8 Job、每Job 8声明、4冲突、12,000字符；超限保留总数及截断标记。

结果：服务器28专项通过，包含原生ReAct/设备调度；全量313项312通过/1环境跳过。原生工程案例登记两个相反目标、形成一个持久冲突，两个上下文确实送达，设备原生工作流仍为2个，Task WAITING，无自动取消或额外时钟请求。未知、取消、重启、截断及不依据未来观测造目标均覆盖。仅工程证据，尚无官方SR收益。

失败保留：v1测试夹具在第二次登记时检查了第一个历史Job，导致测试中断；修正夹具后v2通过，未改上游。归档辅助脚本跨文件系统rename失败，改copy保留；两者零模型调用。

成本：新增模型请求/tokens/GPU预留均0；v2专项1.794秒、全量4.923秒，CPU整理/复核未完整计量。默认G和既有GTME不变；冲突只表示所选动作意图不兼容，不能代替用户目标验证。
