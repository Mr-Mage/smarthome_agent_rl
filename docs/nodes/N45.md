# N45 持久 Scheduler 与监督验证

问题：设备原生计划登记后仍需到点验证；本地定时动作和未来重新规划也必须在重启后继续受任务版本约束。

方案：SQLite Job 区分 device-native/harness-action/agent-wakeup。原生只登记和监督，不重复执行；普通动作到点执行；wake-up 恢复任务目标交给注入的 Agent 回调。事务领取避免重复 dispatch；未知执行仅读回核对；任务改版取消旧计划。

结果：29项累计离线测试通过。原生委托无重复 mutation、双 worker 仅执行一次、重启恢复、修订取消、超时只核对、未来 Job 未完成不得完成 Task、超出时间窗口不执行、取消200不等于已取消。原生取消需要明确状态证据。当前为执行接口验证，未获得公开 benchmark 收益；Persistent Trigger 尚待后续接入。

证据：`execution/scheduler.py`、`tests/test_scheduler_runtime.py`、`runs/task-runtime/n45-v1/`。提交见 `git log -- docs/nodes/N45.md`。
