# N15 Guard v3 与阶段成本

问题：洗碗机/洗衣机/烘干机Start电源依赖漏检；工作流只查询首个设备；episode耗时混入官方评测。

方案：D按公开AST提取准确的OperationalState.Start dead-front检查；W查询每个不同设备，仅检查静态能力，共享40次预算。四actor、64槽、A800 judge，G/GD/GW/GDW，三种子；冻结`configs/guard-v3.json`。计时在项目内包装Agent、工具、等待和评测，不改上游。

结果：77项测试通过；smoke288+dev1,440次完整核验。dev成功G/GD/GW/GDW=126/124/133/124（各360），非法执行57/16/49/36；GD tokens−3.13%，GW−3.11%，GDW+0.07%。GD/GDW成功率下降，GW非法执行降幅14.04%不足30%；全部未过组合门槛，保留G。重复配对CI均含0，不能声称成功率提升显著。

Case：dev seed42、`qt4-3_feasible_seed_21`，GD第7轮拒绝关机Start，随后On→Start→注册Pause，最终成功；本轮G只On后结束，失败。它证明修复生效，不代表每条轨迹都节省token。`qt4-1_feasible_seed_48`中GD仍把三个时间点合并，失败；静态Guard不解决时间语义。原始比较`runs/guard-v3/n15-v1/case-review.json`。

成本：全流程2,121.18秒（含启动、核验、清理），四H100预留资源8,484.71 GPU秒，不是活跃计算时间或费用；无抢占，A800继续常驻。G Agent P50/P95及完整成本见实验报表。首个启动脚本缺少sys导入，在评测前退出，空日志保留；测试首次误用设备API位置参数，修正后全套通过。

证据：`runs/guard-v3/n15-v1/{protocol.json,selection.json,resource-cost.json}`及`smoke/dev/report.json`，原始产物不删除。运行源码`fb06c62`；功能提交`39d4e80`、测试修正`fb06c62`；节点提交见`git log -- docs/nodes/N15.md`。N16按已冻结方案继续，以G为对照。
