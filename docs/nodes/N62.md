# N62 任务与原生调度器接入

问题：原ReAct仅记录工作流登记回执；持久Task/Scheduler此前未接入真实执行链和虚拟时间。

方案：新增可选GTM，保留G的Guard/提示/生成策略。Guard通过后先落盘REGISTERING，再调用原生schedule一次；全部真实工具留Trace。公开时钟驱动Scheduler，工作流完成后读设备状态；取消同步持久映射，未知登记不重放。监督查询与Guard共用40次预算，计入工具/延迟成本；原评测器推进时间后只读公开时钟，不传隐藏目标或deadline。

结果：服务器34项专项全通过，包含真实ReAct与原生Home：登记一次、对话结束后验证、持久重载、取消、漏窗UNKNOWN、Guard拒绝不建Job。全量279项278通过/1环境跳过。本机缺少src/openai，完整检查不可用；报表测试fixture新增计数字段已修复，不改环境。无模型调用或GPU预留。

边界：已验证的仅是Agent所选动作意图；公开用户目标条件未覆盖，Task保留WAITING，不能把Job成功当作任务成功。窗口来自公开模拟器时钟；不自动快进、补执行或重规划。默认G不变，官方收益待独立冻结对照，不重跑N47。
