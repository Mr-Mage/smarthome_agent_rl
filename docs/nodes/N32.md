# N32 独立恢复预算

问题：G的恢复上限依赖Verify而未生效；重复业务错误、观测变化和结果未知需要独立策略。N28任务36/54存在循环，原G另有Channel变更收到500后同参数再次调用。

方案：新增可选`RecoveryPolicy`，GR显式启用，G默认关闭。相同完整参数、错误指纹及相关公开证据下，首次调用加两次修正；跨证据同参数每episode最多6次明确失败。重复相同观测不重置，参数或有效证据变化允许预算内修正。未知变更阻止同参数重放，不吞原异常、不推断成功、不自动补查或重试。仅约束工具领域失败；解析/Guard拒绝仍受既有总步数约束。

结果：冻结[配置](../../configs/recovery-policy.json)，审计192条原公开轨迹：G在1/96条中标记1次未知变更重放；GS在4/96条中标记15次（未知2、局部预算3、总预算10），包含任务36总预算2次及任务54预算11次。标记是历史调用上的策略决策，不是实际省下的调用，也不预测模型重规划、SR或tokens。124项测试123通过、1环境跳过；G关闭策略的192条兼容重放通过，1,415次调用及返回值与旧执行器一致。

修正：v1随设备证据变化重置局部计数，遗漏任务36；v2新增跨证据总预算，两版保留。G唯一触发是qt3可行45、seed44的`Channel.ChangeChannel(match=sbs)`：上游400包装中原始HTTP状态为500，按unknown处理；未知并不证明设备没变。该样本不能作为预算提升SR的证据，本节点未启动在线选优，GR未替换G。

边界：身份按完整参数，不识别改描述/改参数后的语义重复；goal_id、未知调用自动核对及跨进程恢复未实现。上游provider默认11次尝试，SDK还有内层重试，HTTP请求成本仍以完整实测为准，本节点不改网络重试或judge。

证据：`runs/recovery-policy/n32-v1/audit/`、`n32-v2/audit/`冻结输入SHA及逐提案决策，`n32-v2/tests.log`、`g-compatibility/`；审阅包`outputs/recovery-policy/n32-review-v1/`，199个归档文件及192份兼容快照SHA核验通过。离线无模型/网络调用，整理CPU成本未完整采集。分支`feat/recovery-policy`；提交见`git log -- docs/nodes/N32.md`。下一节点N33显式目标覆盖。
