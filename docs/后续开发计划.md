# 后续开发计划：从 N16 时间计划到可归因的 Harness 验收

编制日期：2026-10-05。进展核对基点：`ca89f03`（N15 收尾、N16 冻结）。本文件为后续计划，不代表实验已执行；按功能节点验收推进，不安排日期工期。

## 1. 当前判断与目标

下一步优先完成已实现、已冻结的 N16 TimePlan 实验，然后用开发集证据决定是否继续拆分机制。研究目标是：**在固定 Qwen3.5-9B、官方单轮任务和原实时模拟器下，验证公开约束检查与执行回执能否改善任务成功率，并量化额外成本及失效边界。**

当前最可靠的结论是 G 明显减少了返回非法动作错误的执行次数；总体成功率提升尚未通过既定正式检验。继续叠加 Guard、验证和压缩模块已有负结果，后续应优先解决已有轨迹中“调用合法但计划错误、未完成却结束”的问题。

只做官方单轮 benchmark 的 harness 复现与消融。SFT/RL、语音、多轮、新 benchmark、真实家居部署均不在本计划执行范围。

## 3. 如何吸收《最新调研计划2》

[调研报告](最新调研计划2.md)的“通用 harness 模式”“建议性的 SmartHome Action Contract”“测试、Eval 与 CI”提供架构方向；其中生产化路线、日期与人力估算不直接作为当前实验路线。

| 调研建议 | 当前可落地的最小形式 | 本轮边界 |
|---|---|---|
| 概率规划、确定执行；Typed Tool Contract | 模型给出计划和时间映射，harness 检查公开时间约束、注册参数与回执 | 复用现有 G 和 TimePlan；不换框架、不增加独立平台 |
| Authoritative State 与 Memory 分离 | 记录公开观测的来源、时间及工作流 ID；区分计划、注册成功和执行完成 | 不用模型陈述替代工具结果，不访问隐藏目标或未来状态 |
| Action Contract 与 `uncertain` 状态 | 最小 episode 内动作记录：提案、校验、调用、回执、失败/未知、结束声明 | 超时不推断执行失败；未知状态不宣称成功；不假设上游支持幂等键 |
| Golden Trace 与分层评测 | 固定已有 dev 轨迹重放检查，再跑真实官方任务；记录误拒、漏检和成本 | 离线重放只证明校验机制，不替代在线 SR；不生成新 benchmark |
| Trace 与资源调度 | 延续 N15 的 Agent/评测分段计时，补足时间计划与回执的归因事件 | 先扩展现有审计记录，无需引入整套遥测服务 |
| Durable workflow、恢复与补偿 | 当前仅保留可追溯执行证据，验证明确的状态边界 | 跨进程恢复、自动补偿另行后置；不重放状态未知的副作用 |
| MCP、HA/Matter/MQTT、身份权限、多 Agent | 留作未来部署方向 | 官方单轮任务无法充分验收，当前不实施 |

调研中的外部版本号、性能和生产能力描述未在本次重新联网核验；本计划仅采纳可在项目内验证的设计原则。后续确需依赖某个外部接口时，再核对其原始规范和锁定版本。

## 4. 节点路线与决策门槛

顺序：N16 实测 → N17 机制归因与边界审计 → 有证据才进入 N18 最小修正 → N19 冻结候选及留出验收 → N20 归档。负结果可以通过节点验收；“节点完成”与“增强策略获选”分别记录。N17–N20 为拟定节点，实施前检查编号是否已被其他工作占用。

### N16：完成 TimePlan 的既定配对实验（最高优先级）

**目标。** 验证数值分钟相对时间检查及结束回执能否减少错误时间注册，重点对应 dev 中将 +22、+30、+51 分钟动作合并到同一工作流的真实案例。

**实施。**

1. 只读核对服务器是否已有 N16 运行或产物，避免重复启动；验证代码提交、模型身份、配置/任务哈希、外部 judge 和设备服务。
2. 复核现有时间计划、节点选择和阶段计时测试。重点检查相对时间锚点、step 映射、取消回执、无时钟/未覆盖语义、合法不可行回答，以及 finish 被上游截获时检查仍生效。
3. 保持 `configs/time-plan.json` 的两臂 G/TimePlan、种子 42/43/44、参数与门槛。先 smoke24×2×3=144 次，再 dev120×2×3=720 次，共 864 次。smoke 仅验链路，不选优。
4. 使用现有 `scripts/run_node_experiment.py`；输出到全新 `runs/time-plan/<run-id>/`，逐阶段独立核验，记录失败与全成本。

**冻结的选优条件。** 完整 dev 上同时满足：总体 SR 不低于 G；QT4-1 可行类成功次数严格增加；actor 总 tokens 比例 ≤1.10；非法执行次数不高于 G。执行逻辑以 `smarthome_agent_rl/node_selection.py` 为准，不能看结果后修改门槛。

**验收与分支。** 864 次及证据完整、核验通过、门槛判定可复算，完成节点。通过组合门槛才保留 TimePlan 为开发候选，否则保留 G。总体/分类效应量、配对 CI 与覆盖率一起报告；门槛通过不等于统计显著。发现实现缺陷则保留失败轮，在新版本、新目录重新冻结受影响的完整阶段，不选择性补跑失败任务。

**交付。** 一份 `docs/nodes/N16.md`、实验报表追加记录、配置/提交哈希、`selection.json`、阶段报告、轨迹及成本证据。

### N17：解释 TimePlan 的收益或负收益

**目标。** 分清时间约束表、注册检查和 finish 回执的贡献，以及模型错误映射导致的覆盖缺口。

**先做离线审计。** 只分析 dev：按时间解析未覆盖、锚点/step 映射错误、注册时刻不一致、缺回执、错误不可行判断、预算耗尽分类。每次拦截链接用户原文、公开时钟、提案和工具结果；模型解释与确定性检查结果分字段保存。报告触发次数、涉及的唯一任务数、误拒/漏检、增加的模型轮次和 tokens。

**有触发证据才做在线消融。** 在独立冻结配置中设置 G、G+T、G+R、G+T+R：T 为时间表及注册检查，R 为结束回执检查。共享的计划元数据要求应明确声明，避免把 prompt 改动误归因为确定性检查。各臂共享相同模型与预算，在同一轮跑 smoke24×4×3=288、dev120×4×3=1,440 次；既有 N16 结果仅作参照，不拼接成这一轮的对照。

**验收。** 所有增强行为可归属到模块和证据；各臂完整配对，报告 T/R 主效应与交互的描述性结果及任务聚类 CI。用于后续候选的时间增强仍须满足 N16 四项门槛。多个合格臂按 dev 成功数、总 actor tokens、模块复杂度的顺序选择，并在运行前写入配置。无实际触发或覆盖过窄时，以负证据结束节点，不为增加实验量而运行整套消融。

### N18：仅针对已证实缺口做一次最小修正（条件节点）

**进入条件。** N17 指出可复现、仅依赖用户原文和公开观测的错误，并明确一项可检验改动。如果仅发现模型一般推理不足、隐藏条件缺失或时间表达未覆盖且无法可靠解析，则跳过本节点。

优先修正动作记录/回执的证据边界：记录 task/action ID、参数摘要、观测时刻、workflow ID、工具响应状态和结束声明的对应关系；注册成功只代表已注册，未来执行结果保持未知。未知/失败回执不能被 finish 写成已执行成功。仅在现有公开接口允许且查询预算内核对状态，不引入通用轮询后查，不假设可自动重试、取消或补偿。

**实验与验收。** 先对已有 dev 固定观测重放验证误拒/漏检；随后对照上节点冻结候选做两臂 smoke144+dev720 次。SR 不降、非法执行不增加、actor tokens 比例 ≤1.10，并要求事先定义的目标错误次数下降；若该错误在对照中为零，则该收益条件不可判定。保留完整分类 SR 与延迟结果。一次只改一项机制；未通过即回退候选，不连续在同一 dev 上无上限搜索。

### N19：冻结候选，先审计留出集可用性，再决定正式验收

**前置审计现在就做。** 在读取新任务内容或结果前，枚举所有历史实验使用过的 task ID 与内容哈希，含旧 dev/final、smoke、容量实验和失败轮；统计官方任务池剩余数量与十二类分布。N13 final 和其他已查看任务均不得重新充当未使用留出集。检查近重复和同源模板风险，记录无法证明独立的部分。

**正式实验准入。** 候选及代码、配置、任务清单全部冻结；至少一个开发增强通过预定门槛；官方池中有足够未使用任务支撑预定检验。样本量依据 dev 配对不一致率及事先选定的最小有意义差异估算，不能默认还有新的 192 个任务。池不足时，报告“没有可用的独立正式验收集”，仅保留开发诊断结论；不得重命名旧 final、扩大种子数冒充新增独立任务或生成新 benchmark。

**正式对照。** B0、G、唯一冻结 Candidate；Candidate=G 时合并，避免重复臂。seed42 为主检验，43/44 仅作重复可靠性诊断。三臂三种子的总运行量为 9N（N 为实际冻结留出任务数），分阶段资源预算随清单一并冻结。

**统计协议。** 若 Candidate≠G，主比较为 Candidate−G（增量价值）和 G−B0（既有 Guard 价值），采用任务配对检验及 Holm 校正；Candidate−B0 为次要描述。主终点为官方任务 SR，报告配对 95% CI；三种子汇总按 task 聚类，不能按 3N 个独立样本处理。所有检验、重采样种子/次数和多重比较族在运行前锁定。

**验收。** 正式证据完整、独立复核通过即可结束实验。仅在预声明主检验满足校正 p<0.05、效应方向为正时宣称对应 SR 显著提升；否则报告不确定性并保留负结果。final 结果不能用于改选候选或进入下一轮调参。

### N20：整理复现与结论

保留论文参照、9B 基线、旧正式结果、N15 负结果以及所有新增节点；提供能从冻结配置定位运行入口、原始证据及独立复核结果的索引。更新 README 当前状态；每节点仅一份开发记录，计划文件不代替实验记录。

验收包括：抽取收据重新核验哈希；核对论文/项目任务口径及 judge 身份差异；核对成功数、排除规则与所有失败成本；确认没有把拦截次数、重复样本、离线重放或注册回执包装成独立任务成功。结论允许停留在“执行错误减少，但 SR 改善未证实”。

## 5. 统一实验协议与四卡安排

| 项目 | 执行规则 |
|---|---|
| 模型与环境 | 延续 9B actor、Qwen3.6-35B-A3B judge、现有 Conda/venv；锁定模型/模板身份、依赖与 SimuHome `e202971…`；保留 Lightning 用户补丁 |
| 参数与预算 | 延续 N16 的生成参数、max_steps=20、每动作恢复上限 2、额外查询上限 40；改动另立诊断配置，不混入主比较 |
| H100 | GPU0–3 各一个 actor；每 actor 16 独立模拟器槽，共 64 槽。每个 task×seed 的对照臂固定到同一 actor，平衡不同任务到四卡；启动前核查调度器实际映射 |
| 外部 judge | 2×A800 评测服务；检查 health/models、模型身份和连通性；单独记录其请求量、tokens、排队与服务异常，不由本轮脚本擅自重启 |
| 并行与隔离 | 四卡优先并行同轮配对臂；GPU、模拟器状态、Gateway/模拟器端口、run 目录分别隔离。额外 CPU 离线诊断可并行；额外 GPU 实验待主轮释放资源或预先冻结独立资源分区后运行 |
| 压力控制 | 沿用 0.8 actor 显存利用率配置，记录 KV 峰值、抢占、队列、OOM、judge 瓶颈；出现资源故障先判定该阶段有效性，不运行中偷偷减槽改变条件 |
| 实时动力学 | 保持原时钟与调度规则；不通过虚拟时钟、加速等待或修改 evaluator 缩短评测。并发引起的轨迹差异写入局限 |
| 排除与失败 | 保留普通任务失败和未完成；基础设施错误按冻结规则使整个受影响阶段无效，保留原始记录及成本，在新目录完整复跑 |
| 主实验与额外诊断 | smoke、固定观测重放、覆盖分析、可靠性重复、容量实验单独标记；均不能替代预声明主检验 |

运行前还需处理现有 runner 的“工作树必须干净”要求：将本节点冻结内容提交或部署到隔离干净 checkout；保留用户未提交的调研文档，不擅自提交、删除或 stash 用户文件。

统一记录：SR 与分类 F/IF、配对差及 CI；非法执行/错误提案/误拒/额外查询；actor 与 judge 输入输出 tokens；包含失败的 tokens/成功数；Agent、工具、检索、等待、评测和完整 episode 的时间；P50/P95；模型启动、报告核验、失败与清理成本。actor HTTP 时间包含排队、网络和 Gateway，不等于 GPU 计算时间。H100 预留 GPU 秒与 A800 成本分别记录，缺少分摊证据时写“未分摊”，不写零；无单价时不换算货币。

## 6. 版本、产物与停止条件

每个完成节点在功能分支独立提交；源码放现有 `smarthome_agent_rl/` 与 `scripts/`，配置放 `configs/`，测试放 `tests/`。仅新增一份对应的 `docs/nodes/N*.md`，简述问题、方案、结果、提交与证据。实验产出即追加 `docs/实验报表.md`；进行中标暂定，不覆盖历史失败。

原始运行放 `runs/<方向>/<run-id>/`，临时脚本与中间文件放 `work/`，审阅包可沿用已忽略的 `outputs/`；均不入 Git。节点结束整理索引与哈希，保留唯一证据。既有 `docs/后续实验方案.md` 保留为 N14–N16 历史方案，本文件承接其后的决策路径。

以下任一条件成立即停止增加增强模块，转入结果整理：N16/N17 没有可验证收益且缺少新的公开证据；新增检查主要增加成本或误拒；留出任务不足；所需能力已越过单轮 harness 范围。生产化方向只有在项目范围另行改变后再规划。

**下一步具体动作：核对服务器 N16 状态与冻结身份，同时离线清点未使用官方任务；确认未重复运行后，执行既定的 144 次 smoke 和 720 次 dev。当前计划编制不启动这些实验。**

## 执行结果

N16有效864次核验完成，增强未过门槛；N17离线审计完成，依据成本增加和留出不足停止在线消融；N18未进入；N19剩95个任务、无合格增强，正式实验未准入；N20归档完成。最终保留G，停止新增模块；详见[N16](nodes/N16.md)、[N17](nodes/N17.md)、[N19](nodes/N19.md)、[N20](nodes/N20.md)与[实验报表](实验报表.md)。上述正文保留为执行前冻结计划。
