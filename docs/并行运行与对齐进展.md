## 开发对齐的具体变化

- 新生成器不读取官方 benchmark，包含跨房间灯控、三灯批量控制、亮度数值控制、风扇速度和供电前置条件，共16个固定任务。每项至少一个目标初始不满足，并检查另一房间设备保持原状。
- reference action plans 单独用于 CPU simulator 可达性验证，不放进 Lightning task input，不作为 agent 的决策或自动纠错。agent仍从官方工具发现设备并自主执行。
- 每个分片包含四类任务，分别8项。两种 harness 都通过用户现有 Lightning runner，预计总计32次 online rollout；失败也保留。没有重写原ReAct循环，也没有用benchmark调prompt。
- 先冻结比较最小的schema-only变体，不在新结果出现前加入或调整恢复提示。当前一次运行/配置，不宣称稳定因果收益；GPU/分片也不是实验变量。
- runner新增可配置模型路径、tensor parallel、memory budget与engine seed，保留旧配置默认值。user_location支持task显式字段，避免多房间任务被默认定位到第一间房。
- success继续要求实际环境目标满足、原agent合法finish、正常执行；reward及Lightning模型请求/token IDs沿用独立校验器。开发reward不冒充官方benchmark评分。

## 恢复后启动

将本轮项目文件同步到既有H100项目，再进入该目录，一条命令并行启动官方流程与开发。目录名必须尚不存在：

```bash
bash scripts/run-parallel-h100.sh --run-dir runs/parallel-20261003-01
```

监督入口 `run_parallel_workflows.py` 先检查两线GPU/端口分配以及preflight与shards任务一致，然后立即启动原CLI流程和CPU preflight；preflight成功后启动两卡开发。某条实验线失败仍让另一条继续，保存 `workflow_status.json`、实际命令/PID和各线日志。进程停止仅针对本次启动对象。

Qwen3-32B完整下载并校验后，使用新目录和对应配置，不覆盖前一轮：

```bash
bash scripts/run-parallel-h100.sh \
  --reproduction-config configs/reproduction-qwen3-32b.json \
  --run-dir runs/parallel-qwen3-20261003-01
```

独立入口仍可分别运行：

```bash
bash scripts/reproduce-h100.sh --config configs/reproduction-smoke.json \
  --run-dir runs/official-cli-smoke-20261003-01
bash scripts/run-parallel-dev-h100.sh --run-dir runs/parallel-dev-20261003-01
```

原仓库复现的模型、judge、embedding及论文数据边界见 `原仓库复现进展.md`；权重来源、断点下载和校验见 `复现模型下载记录.md`。本轮未进行SFT/GRPO、多模态、付费API调用，未修改或打包SimuHome源码。
