## 目标与方案

研究在同一模型、同一任务与预算下，harness 改进、SFT、RL 分别能带来多少任务成功率提升，以及多少调用和 token 成本变化。第一阶段仍是纯文本、symbolic 智能家居任务。

主线：**Qwen3.5-9B + ReAct 基线 → harness 优化对照 → SFT → RL。** 后两步在基线、数据和指标可靠后实施。

- SimuHome：复用环境、状态转移和工具能力；不修改或重发布源码。
- Agent Lightning：继续使用已跑通的环境，组织真实 rollout、记录调用与 reward，并衔接后续训练。
- Agent：复用现有 ReAct 循环和工具，固定本项目的提示词、配置和结束规则，作为自己的 B0 基线；无需为建立自己的基线重新写一套 agent。
- 数据与评价：独立生成 train/dev/test；模型优化只看 train/dev，test 保持未见。成功依据实际设备状态与合法结束，同时记录非法操作、调用数和 tokens。

## 后续动作与原因

| 顺序 | 动作 | 原因与验收 |
|---|---|---|
| 1. 模型就绪 | 下载、哈希校验，验证加载与纯文本工具调用；固定 thinking、采样、上下文和调用预算 | 避免把推理配置变化混入 harness 或训练收益 |
| 2. 自己的基线 | 先用现有 16 项任务检查链路，再在固定 dev/test 上跑未训练的 9B + ReAct；保存 B0 配置和结果 | 得到可重复、可比较的起点；无需追求原论文数字 |
| 3. Harness 优化 | 按失败类型逐项改输出契约、参数反馈或结束验证，保持模型与任务不变并复测 | 证明改进来自哪一类机制；保留成功率和成本的完整对照 |
| 4. SFT | 独立生成训练任务，采集并验证轨迹；先进行小规模 LoRA 训练与评测 | 先检验训练是否学会正确工具行为，降低首次训练的资源与排障成本 |
| 5. RL | 在已验证的配置上接入在线 rollout 与环境 reward，先小预算实验 | 对比 SFT 与 SFT+RL；只有观测到有效收益才扩大预算 |

实验分别保留“只改 harness”和“只改模型权重”的对照，不同时改两者后笼统宣布提升。数据需按家庭布局、设备组合和任务组合分开，避免仅换 seed 却泄漏相同任务。
