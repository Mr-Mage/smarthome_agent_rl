## 失败分析与记账修复

实际轨迹暴露了三个问题：

- 结构化输出能约束工具外层参数，但不能自动确保 Matter cluster/command/attribute 合法。例如 dimmer-3 选择不存在的 DimmableLight cluster；fan-1 为 FanMode 提供字符串 MEDIUM，未使用设备要求的数值表示。
- 设备定位与执行规划仍会出错：有的任务操作了保护设备，有的只控制部分灯就 finish。fan-3 在执行失败后调用 remove_device 删除风扇，随后结束；环境 verifier 保留这个失败。
- 原 ReAct 连续第三次格式拒绝会抛异常，未发出该次 observation。旧外部采集漏算最后一次模型调用成本，导致 9 次模型请求只有 8 个环境记录。

第三个问题已在外部 accounting/observer 修复：只对原 AgentExecutionError 的明确连续拒绝事件补记 rejection、invalid 和真实调用成本；不反馈额外 observation，不改变原 agent 的控制流，不把网络故障计成 agent 非法动作。新增测试直接执行未修改的原 ReAct，验证第三次拒绝无反馈的行为。

新结果 metrics_version=4；第三次拒绝的单独 observer 事件保存在 observer_events.json，原 upstream_events.json 保持原 trace。旧失败运行保留，未重写历史指标。全部 13 项检查通过，记录在 `logs/single-h100-tests.log`。
