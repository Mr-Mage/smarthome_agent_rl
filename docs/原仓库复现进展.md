## 已核查的协议

固定上游 commit `83d28837b69f0cbf1bc02ed5334cb8b561a9d54d`，直接执行 `python -m src.cli.main eval-start` 和 `aggregate-all`。这与官方 `uv run simuhome` 的同一 CLI 实现入口一致；使用已经安装完整依赖的独立 Python 3.13 环境，不修改 Agent、工具、simulator 或 evaluator。

首轮选 qt3 feasible seeds 1、2、3，原 ReAct、temperature 0、provider seed 42、max_steps 20、timeout 60。官方 qt3 feasible evaluator 同时检查 required_actions 和设备 attribute asserts。只满足目标、不包含所需工具调用仍判失败；使用原聚合器保留 model failure 与 infra failure 的区别。

官方 evaluation spec 要求 api/judge/model 配置。`api_key: null` 配合 `127.0.0.1` 被原 config resolver 合法解析为 dummy；并非缺少必填密钥。qt3 feasible evaluator 不调用 judge，原 CLI 仍创建 3 个 judge provider，配置指向同一个本地地址并使用特意不存在的 `unused-simulator-only-judge` 名称，防止意外调用被混同为正常评测。

全部 OpenAI 环境地址和 API 配置明确为本地，复现脚本不使用外部付费 API。原 `search_matter_docs` 若被模型调用，已有 FAISS 索引会读取，但 query embedding 仍需要服务；目前 vLLM 文本生成服务不支持该 embedding API，所以这类调用会由原工具返回错误。不能称之为完整文档检索能力复现。首轮未替换该工具，也未屏蔽其错误。

## 模型与论文结果边界

当前 H100 只有已经使用的 Qwen2.5-1.5B-Instruct；首轮以此做官方流程试跑。这不是论文模型，不称作论文表 1 结果复现。

论文 A.7 明确列出 Qwen3-32B，并说明所有模型都经 OpenRouter 访问。下一套配置指定官方 `Qwen/Qwen3-32B`，固定 revision `9216db5781bf21249d130ec9da846c4624c16137`，未量化原权重，TP=2 使用 GPU 0、1。官方模型支持 32768 原生上下文，默认 thinking 开启；原论文/仓库未明确本地 serving 的 thinking 参数。不能把本地 vLLM 与 OpenRouter 的行为、generation defaults 和性能视为完全等价。[论文 A.7](https://arxiv.org/html/2509.24282v1#A7)、[官方模型卡](https://huggingface.co/Qwen/Qwen3-32B)

仓库 README 说明当前 benchmark 在论文提交后重新生成，使用增强后的 simulator，并非论文表 1 的原数据。即使型号和协议相同，也不能期待精确复现表中数字。全量 qt1 和 infeasible 类别还需要官方 judge；当前仅推进无需 judge 的 qt3 feasible 试跑，没有把本地 1.5B 替成 judge。

## 可复跑命令

在 H100 的 `smarthome_agent_rl` 项目目录运行，目录名称必须是新的，避免覆盖历史记录：

```bash
bash scripts/reproduce-h100.sh \
  --config configs/reproduction-smoke.json \
  --run-dir runs/official-cli-smoke-20261003-01

# 下载并哈希校验 Qwen3-32B 完成后才运行：
bash scripts/reproduce-h100.sh \
  --config configs/reproduction-qwen3-32b.json \
  --run-dir runs/official-cli-qwen3-32b-20261003-01

# 只生成配置、seed 哈希与依赖存在性记录，不启动模型：
bash scripts/reproduce-h100.sh \
  --config configs/reproduction-qwen3-32b.json \
  --run-dir runs/official-cli-qwen3-32b-preflight-20261003-01 \
  --preflight-only
```

输出包含 `config.json`、`preflight.json`、完整原始 `evaluation_spec.yaml`、`commands.json`、`model.log`、`official-cli.log`、`official-aggregate.log`、原始 `official/manifest.json`、run state、原评测记录及 aggregate。正常结束会生成 `verification.json`；失败会写 `failure.json`，保留失败目录。

脚本前后检查上游 git status 为干净，仅终止自己启动的进程组。原始 CLI 子流程 errors 和 score 不由外部脚本重写。局部 qt3 样本只检查复现流程，不能作为全 benchmark 成功率，也不用于训练或 harness tuning。
